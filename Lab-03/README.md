# Laboratorio Semana 4: Seq2Seq Ingles-Espanol desde cero

## Summary

Starter notebook (corpus, vocabularies, and initial weights given, not to be modified) where the task was to fill in an Encoder-Decoder LSTM pipeline — `oracion_EN -> [Encoder LSTM] -> c = h_T^enc -> [Decoder LSTM] -> W_out + softmax -> prediccion` — using raw PyTorch tensors only (no `nn.LSTM`, `nn.Embedding`, `nn.Linear`, no `loss.backward()`). The corpus pairs EN/ES sentences with deliberately mismatched lengths (subject elision, verbal periphrasis), so the completed encoder/decoder loops have to handle asymmetric sequence lengths without any special-casing.

- **Blocks 0–1 (given)**: Corpus (78 pairs, 75/25 train/test split), vocab builders, tokenizers, and the fixed initial weights (`d_emb=16`, `d_hid=32`) were provided.
- **Block 2 — Encoder forward**: Filled in `lstm_cell` (the five LSTM gate equations) and `encoder_forward`, looping over the source tokens and caching each step's intermediates for backward.
- **Block 3 — Decoder forward**: Filled in `decoder_forward` with teacher forcing, running exactly `len(dec_input_indices)` steps regardless of how that compares to the encoder's length.
- **Block 4 — Loss**: Filled in categorical cross-entropy over the decoded sequence via `F.log_softmax`.
- **Blocks 5–6 — Manual BPTT**: Filled in the backward pass by hand — decoder gradients first (output layer, then gate-by-gate BPTT), handing off `dL_dh_context`/`dL_dc_context` into an equivalent backward loop over the encoder.
- **Block 7 — Sparse embedding gradients**: Filled in a dictionary-based version of the embedding gradient (only columns touched by the sequence) and compared it against the dense version — mostly to observe that, at this toy scale, the "efficient" version is actually slower due to Python-loop overhead.
- **Block 8 — Parameter update**: Filled in the vanilla gradient descent update for all ten weight tensors plus both embedding tables.
- **Block 9 — Training loop**: Filled in the full per-pair loop (forward, loss, backward, update) reusing the logic from blocks 2–8, run for 5 iterations over the 58-pair training set.
- **Block 10 — Greedy decoding**: Filled in `greedy_decode` (argmax at each step, stop at `EOS` or `max_len`).
- **Blocks 11–12 (analysis, given as questions)**: Plotting cell was given; wrote the answers to the three analysis questions on gradient path length vs. output length, what the context vector has to encode for the decoder to stop at the right point, and how the exercise would change if turned into an autoencoder.
- **Block 13 (given)**: Automatic grading cell — self-reports 60/60 on the code section (all block-level hash/assertion checks passed).

## Notebook Walkthrough

- **Data**: 78 EN/ES pairs (58 train / 20 test, seeded 75/25 split); EN vocab has 158 words, ES vocab 163. Target/source length differs in 70/78 pairs (57 shorter in Spanish, 13 longer), by design — the elision/periphrasis asymmetry described above.
- **Verification pair**: `they play soccer -> juegan futbol` — 3 encoder steps, 3 decoder steps (`[juegan, futbol, EOS]`). Every intermediate block checks its output against a precomputed hash or tolerance on this pair.
- **Forward results**: initial `loss_mean ≈ 5.0933` on the verification pair (close to `-log(1/163)`, i.e. random at initialization).
- **Sparse-gradient comparison (Block 7)**: only 3 of 158 embedding columns received a nonzero gradient on the verification pair; the dictionary-based update (17.98 µs) actually ran slower than the dense one (4.48 µs) at this scale — Python-level dict iteration overhead outweighs the saved arithmetic when the vocab/embedding size is this small.
- **Training loop (Block 9)**: loss over 5 full-corpus iterations went `5.0736 -> 5.0318 -> 4.9904 -> 4.9493 -> 4.9087` (3.25% reduction), plotted in `convergencia_seq2seq.png`.
- **Greedy decoding (Block 10)**: 0/20 (0.0%) first-word accuracy on the test set after only 5 iterations — expected, since 5 passes over 58 pairs is nowhere near enough to learn a working translation model; the block exists to exercise the decoding loop and the length-asymmetry handling, not to produce a usable translator.
- **Automatic grading cell (Block 13)**: reports 60/60 on the code-check section (blocks 2, 4–9 all pass their hash/assertion checks).
- **Analysis answers**: cover (1) how gradient path length ($S+T$ LSTM steps) differs between short- and long-output pairs and what that implies for curriculum learning; (2) why first-word accuracy is a more informative (if limited) signal than training loss, an estimate of how many vocabulary words never receive a gradient update given the corpus size, and two architectural options for a bidirectional EN↔ES model; (3) the three code changes needed to turn the pipeline into a Spanish autoencoder, how the gradient path length would change, and whether `d_hid=32` (64 floats across `h`/`c`) is enough to encode the corpus's longer sentences.
