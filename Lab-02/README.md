# Laboratorio Semana 3: LSTM desde cero con PyTorch

## Summary

Starter notebook (data generation, fixed weights, and verification cells given, not to be modified) where the task was to fill in a complete LSTM pipeline — `Secuencia x_1..x_T -> LSTM (T pasos) -> h_T -> Dense + sigmoid -> BCE` — entirely from scratch using raw PyTorch tensors, covering both the forward pass and a fully manual backward pass (BPTT) through every gate. The task is a many-to-one binary classification: determining whether a synthetic sequence of 5 two-dimensional points has an increasing or decreasing trend, without using `nn.LSTM`, `nn.RNNCell`, `nn.Linear`, or `loss.backward()`.

- **Forward pass (filled in)**: A single `lstm_cell` step implementing all five LSTM equations (forget, input, candidate, cell state, output/hidden state) via `torch.cat`, `torch.sigmoid`, `torch.tanh`, and `@`, looped over `T=5` timesteps while caching every intermediate needed for backward; final hidden state `h_T` feeds a dense layer + sigmoid to produce `y_hat`, followed by BCE loss.
- **Backward pass (filled in)**: Manual backpropagation-through-time — dense layer gradients from the closed-form `y_hat - y` simplification, then a reverse-order loop over timesteps computing gradients for each gate (`o_t`, `c_t`, `f_t`, `i_t`, `c̃_t`) through their sigmoid/tanh derivatives, accumulating weight gradients with `+=` across all timesteps, and propagating `dL_dh_next`/`dL_dc_next` to the previous step.
- **Weight update & convergence check (filled in)**: One gradient descent step ($\alpha = 0.01$) on all 10 parameter tensors, followed by a 5-iteration training loop re-running forward + backward + update each time, verifying the loss decreases monotonically.
- **Analysis questions (given as questions, answers written)**: Discussion connecting BPTT mechanics to vanishing/exploding gradients — the two contributions summed into `dL_dc` and what breaks if `+=` is replaced with `=`, the consequence of a forget gate fixed at zero, and how gradient scaling through the cell-state path differs from a vanilla RNN as sequence length grows to `T=50`.

## Notebook Walkthrough (`LSTM.ipynb`)

- **Data & fixed weights**: Synthetic increasing sequence `x_seq` of shape `(T=5, n=2)` with label `1.0`; hidden dimension `d=4`. All gate weights (`W_f, W_i, W_c, W_o`, shape `(4,6)`) and `W_dense` (`(1,4)`) are seeded (`torch.manual_seed(0)`) small random values, biases start at zero, learning rate `alpha = 0.01`.
- **Forward pass results**: `lstm_cell` applied over the 5 timesteps yields `h_T` (verified against a reference hash), then `z_dense = W_dense @ h_T + b_dense` and `y_hat = sigmoid(z_dense) ≈` the value giving `loss ≈ 0.692664` — close to `-log(0.5)`, i.e. essentially random at initialization.
- **Backward pass results**: `dL_dz_dense = y_hat - y` seeds the backward; BPTT loop propagates gradients through `o_t`, `c_t` (summing the direct cell-state route and the route through `h_t`), `f_t`, `i_t`, `c̃_t`, and their activation derivatives, accumulating `dL_dW_f, dL_dW_i, dL_dW_c, dL_dW_o` and biases across all 5 timesteps.
- **Weight update & convergence**: All 10 parameters updated via vanilla gradient descent; a fresh 5-iteration training loop (reusing the same forward/backward logic) confirms the loss decreases monotonically from `0.692664` down to a lower value, plotted in `convergencia_lstm.png`.
- **Analysis answers**: Cover why `dL_dc` needs two summed terms (the direct `c_{t+1}` route via `f_{t+1}` vs. the route through `h_t`) and why replacing `+=` with `=` would silently turn the LSTM into an RNN by deleting the cell-state edge; what happens when `f_t = 0` (cell state loses all memory, gradient through `c_t` vanishes every step); and how gradient scaling compares between a vanilla RNN (`‖W_h‖^{T-1}` decay) and the LSTM's cell-state path (product of forget gates, avoidable rather than structurally guaranteed) as `T` grows from 5 to 50.
